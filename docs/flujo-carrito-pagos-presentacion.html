Flujo de compra

Carrito, Stripe, stock, pedidos y emails. La idea clave es sencilla: el carrito no reserva stock; la compra se confirma cuando Stripe paga y el backend crea el pedido.

Carrito y stock

Antes de pagar solo se guarda una intención

Frontend

El usuario elige

Producto, talla y cantidad. Angular llama al servicio de carrito para guardar esa selección.

Backend

CartService.add

Valida que el producto sea comprable, normaliza la talla y limita la cantidad al stock disponible.

cart_items = user_id + product_id + size + quantity

Importante: añadir al carrito no descuenta stock real. Dos usuarios pueden tener la misma última unidad en su carrito; gana quien complete el pago primero.

Pago con Stripe

El backend crea una sesión Checkout

  • PaymentService.createCheckoutSession obtiene el usuario actual y lee su carrito.
  • Crea los line items con nombre, precio, cantidad y datos del producto.
  • Stripe devuelve una URL de pago y el frontend redirige al usuario.
  • La sesión se guarda como PENDING en stripe_checkout_sessions.
PaymentService.createCheckoutSession() -> Session.create(...) -> stripe_checkout_sessions = PENDING -> devuelve URL de Stripe
PENDING

Creada

La sesión existe, pero todavía no se ha creado pedido.

PROCESSING

Procesando

El backend está descontando stock y creando el pedido.

COMPLETED

Finalizada

El pedido ya existe; si Stripe avisa otra vez, no se duplica.

Pedido real

El stock se comprueba justo antes de crear el pedido

  • Stripe confirma el pago por webhook o por la vuelta del usuario a la app.
  • fulfillPaidCheckout comprueba que paymentStatus sea paid.
  • CartService.checkoutPaidCartForUser vuelve a leer el carrito y los productos actuales.
  • Si ya no hay stock suficiente, lanza error y no crea pedido.
  • Si hay stock, descuenta unidades, crea orders y order_items, y vacía el carrito.
fulfillPaidCheckout(stripeSession) -> comprueba paymentStatus = paid -> marca PROCESSING -> cartService.checkoutPaidCartForUser(userId) for item in cart: product = findById(item.productId) sizeStock = stockForSize(product, item.size) if quantity > sizeStock: error "No hay stock suficiente" updateStock(...) create order

Emails y mejora

Después del pedido llega la confirmación

Email

MarketingEmailService

Tras crear el pedido se llama a sendOrderConfirmationEmail. El correo HTML incluye productos, tallas, cantidades y total.

@Async

Segundo plano

Los emails de bienvenida, lanzamientos, reposición y pedidos se mandan sin bloquear al usuario.

Mejora recomendada: si dos pagos de la última unidad llegan exactamente a la vez, lo más sólido sería descontar stock con una operación atómica en SQL o bloquear la fila del producto durante el checkout.
